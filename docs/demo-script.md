# Fintor — demo narration script

The 9 beat timings below total 9.64 min and come from the synthetic reference track, which is paced differently from the voice that shipped. Treat them as relative targets for a re-recording, not as clock positions in the finished film.

Generated from `scripts/narration.toml`; the beat durations are measured from the rendered reference clips, not estimated. Do not edit this file by hand — edit the TOML and re-run `scripts/write_script.py`.

## Recording it yourself

The footage is already cut to these timings, so you do not have to match them exactly — but the closer you land, the less drift at the end.

1. Record each beat as its own file, named `NN-<id>.m4a`, into `build/demo/audio/` (replacing the synthetic clips), **or** record one continuous take.
2. Re-run the mux:

   ```
   # per-beat files already in place
   .venv/bin/python scripts/mux_demo.py

   # or one continuous take
   .venv/bin/python scripts/mux_demo.py --audio path/to/narration.m4a
   ```

The video is never re-recorded. Only the audio is replaced.

This writes `build/demo/demo_mux.mp4`, not the file the app plays. The committed `docs/demo.mp4` is a copy of the finished mix from `scripts/remix.py`; replacing it is a deliberate step, not a side effect of re-running the mux.

> Prices are fetched on demand, and a visible marker always says whether what you are looking at is live, a saved copy, or the last known value.
> That matters more than it sounds.
> When a data source fails, this degrades through four stages rather than inventing a number or showing a blank.
> Price history, with twenty and fifty day moving averages drawn in grey as context, rather than as competing coloured lines.
> The price is the subject.
> The averages are reference.
> Change over the period.
